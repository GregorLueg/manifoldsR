# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working
with code in this repository.

## What this package is

`manifoldsR` is a thin R wrapper over Rust. Every algorithm (UMAP, tSNE,
densMAP, den-SNE, PHATE, PacMAP, diffusion maps, EVoC, k-means) lives in
external crates (`manifolds-rs`, `ann-search-rs`, `evoc-rs`,
`bixverse-rs`). The Rust code in `src/rust/src/` is a translation layer
only: it parses R lists into the crates’ parameter structs, dispatches
fp32/fp64, and converts matrices. If an algorithm needs a real change,
it belongs upstream in the crate, not here.

## Commands

``` r

rextendr::document()          # rebuild Rust + regenerate R/extendr-wrappers.R + roxygen
devtools::load_all()          # load without reinstalling
devtools::check()             # full R CMD check
tinytest::run_test_file("inst/tinytest/test_umap.R")   # single test file
tinytest::test_package("manifoldsR")                   # all tests
```

`DEV_BUILD=1` (env var, read by `tools/config.R`) keeps
`src/rust/target` and the shared cargo registry warm and drops LTO. Use
it for iteration; never for benchmarking or a release. There is no debug
profile. The package always builds `--release`.

Rust-only checks are faster via `cargo` directly:

``` bash
cargo check --manifest-path src/rust/Cargo.toml
cargo clippy --manifest-path src/rust/Cargo.toml
```

## Layout and generated files

- `src/Makevars` and `src/Makevars.win` are generated by `configure` -\>
  `tools/config.R` from the `.in` templates. Edit the templates, never
  the output.
- `R/extendr-wrappers.R` is generated by the `document` bin
  (`src/rust/document.rs`) during the cargo build. Do not edit. Roxygen
  on the `rs_*` functions is written as `///` doc comments on the Rust
  side and flows through into this file.
- `.copier-answers.yml` marks the files owned by the
  `personal-templates` copier template (`configure`, `cleanup`,
  `tools/`, `Makevars.*.in`, CI workflows). Changes there get
  overwritten on the next `copier update`.

## The per-algorithm pattern

Each method repeats the same five-part structure. Follow it exactly when
adding one.

1.  `params_<algo>()` in `R/params.R`: a wrapper returning a named list
    of algorithm parameters with `match.arg` +
    [`checkmate::qassert`](https://mllg.github.io/checkmate/reference/qassert.html)
    on each.
2.  `check<Algo>Params()` / `assert<Algo>Params()` in
    `R/checkmate_extensions.R`: the `check*` function returns `TRUE` or
    an error string; the `assert*` is built with
    [`checkmate::makeAssertionFunction()`](https://mllg.github.io/checkmate/reference/makeAssertion.html).
3.  `.prepare_<algo>_params()` in `R/<algo>.R`: merges `nn_params` with
    the algorithm params into one flat list, applies data-dependent
    defaults (e.g. UMAP picks `n_epochs` from `n` and the optimiser).
    Exported but `@keywords internal`.
4.  `<algo>()` in `R/<algo>.R`: the user-facing function. Coerces data
    frames to matrices, validates, then branches on whether a
    `NearestNeighbours` object was supplied: `rs_<algo>_from_knn()` if
    yes, `rs_<algo>()` if no. Both calls are wrapped in `tryCatch` that
    rethrows with a prefixed message.
5.  `src/rust/src/<algo>.rs`: an `Internal<Algo>Params<T>` struct with a
    `from_r_list()` that pulls each key out of a `HashMap<&str, Robj>`
    with a fallback default. The corresponding `rs_*` function goes in
    `src/rust/src/lib.rs` and must be registered in the
    `extendr_module!` block there.

The flat-list handoff means R and Rust agree on parameter names by
convention only. A rename on one side silently falls back to the Rust
default on the other. Check both.

## Cross-cutting conventions

- **Precision**: `parse_precision(use_high_precision, nrows)` in
  `lib.rs` picks fp32 below `SAMPLE_THRESHOLD_HIGH_PRECISION` (100k
  samples) and fp64 above, unless the user forces it. Every `rs_*`
  embedding function duplicates its body across an fp32 and an fp64
  match arm. Keep both in sync.
- **Verbosity**: R side accepts `TRUE`/`FALSE` or `0L`/`1L`/`2L`,
  converted by
  [`parse_verbosity()`](https://gregorlueg.github.io/manifoldsR/reference/parse_verbosity.md)
  in `R/utils.R` to an integer passed to Rust as `verbose`.
- **kNN reuse**:
  [`generate_knn_graph()`](https://gregorlueg.github.io/manifoldsR/reference/generate_knn_graph.md)
  returns a `NearestNeighbours` S3 object holding flat sorted
  `indices`/`dist` plus `k` and `n`. Every embedding method accepts it
  via the `knn =` argument to skip the search.
- **S3 classes**: `NearestNeighbours`, `Evoc`, `KMeansCluster` are all
  plain lists with a class attribute, constructed in `R/classes.R` with
  getters as generics. No S4, no R6.
- Deprecations go in `R/deprecated.R` using
  [`lifecycle::deprecate_warn()`](https://lifecycle.r-lib.org/reference/deprecate_soft.html).

## Tests

tinytest, in `inst/tinytest/`. Each file sources `./utils_test.R` for
the shared helpers (`check_cluster_separation()`,
`density_preservation()`, `check_branch_topology()`). Tests use
synthetic data from `rs_data_*` with a fixed seed and assert
structural/topological properties (cluster separation, density
correlation, branch ordering) rather than exact coordinates. Embeddings
aren’t bit-reproducible across the fp32/fp64 paths.

`misc/workbench.R` is a scratch file for benchmarking against `phateR`,
`uwot`, `Rtsne`. Not part of the build.
